v0.109 — Current developer handoff (delivery candidate)

This is an early-development Windows game. The 0.100-0.109 sequence improves existing systems; it does not establish Starsector parity or a finished commercial-quality game. See CODE MAP.md for code navigation and the individual CHANGES files for exact receipts and remaining limits. Previous verbose notes are preserved in docs/history/quality100-108/DEVELOPER NOTES before109.txt and Git.

Keep: 36 original boat designs; compatible interchangeable physical mounts; bronze coins and conserved worker/business/government/fleet purses; total fleet ownership separate from 300-point battle deployment; 48 seeded island groups on an ocean world with no major continents; Open Seas between groups. Water remains inexpensive. Crew are numerical except figures already in boat assets. User music, saves and settings are preserved.

Architecture: authoritative combat is a detached 30Hz data worker with staggered role/target decisions; main owns scene/input, publication, interpolation, render submission, UI and audio. Automatic saves defer while economy work is pending. Explicit saves and retirement still settle and verify complete data. The 101 payload optimization is a measured small constructor improvement, not proof of overall FPS.

Current delivery: local scopes100-108 accepted and packaged in order.109 media/store/download work is pending. Public version and installed version must be recorded separately. Do not claim dense 300-point smoothness, audio listening quality, sinking/recoil polish or whole-game balance from small fixtures, raw screenshots, export or startup. Larger-case rendering and daily publication/serialization remain practical performance concerns.

Lessons to retain:
- Read and write UTF-8 explicitly. Preserve mixed line endings in surgical source edits.
- Confirm API return meaning. set_autopilot(false) returns disabled state; queue success and actual successful receipts are separate.
- Wait on the original exported GUI process handle. Shell completion can occur before a GUI game exits.
- A whole test job includes import, initialization, native checks, export, startup and teardown. Reuse completed evidence instead of replaying heavy checks. Failed or interrupted jobs remain failed even when an earlier phase passed.
- Use one shared test lane, owned process identity, private profile and silent background session. Never interrupt another game or take input control. Current selected passes are capped at60 seconds with an owned55-second backstop.
- Inspect raw images AND the full rendered customer page independently. Hashes and image counts cannot establish visual quality or useful gallery variety. Use distinct real modes and worthwhile framing, with no fake effects or fabricated wealth.
- Preserve actual earned state and finite money/material transfers. Wages already paid, future reserve allowance, client escrow and cargo consumption are not interchangeable accounting entries.
- Validate the exact source/export template and keep candidate code frozen during native jobs. The self-contained Godot toolchain reads templates from its editor_data folder.

Style-specific owner requirements: plain useful UI wording, no slogans or captions on passive scenery; low-poly/isometric boats, inexpensive water, a Windows-first control scheme. General practices above transfer to other projects. Board watch remains PAUSED.
