Insert these definitions into Goods.ITEMS using the existing input/labor/weight
schema. They are also returned as independent dictionaries by specs().

    "input": {"food": 1.0},
    "labor": {"fisher": 0.10, "carpenter": 0.04},
    "weight": 1.0
},
"fine_timber": {
    "input": {"logs": 1.0},
    "labor": {"carpenter": 0.16},
    "weight": 1.0
},
"lacquer": {
    "input": {"logs": 0.25, "charcoal": 0.25},
    "labor": {"woodcutter": 0.05, "refiner": 0.08, "carpenter": 0.08},
    "weight": 0.5
},
"medicinal_plants": {
    "input": {},
    "labor": {"farmer": 0.20},
    "weight": 0.25
}

Per lot, at the supplied wages:
- preserved_fish: 0.14 worker-days; 15 coins labor, plus Goods.cost("food").
- fine_timber: 0.16 worker-days; 20 coins labor, plus Goods.cost("logs").
- lacquer: 0.21 worker-days; 25 coins labor, plus 0.25 times each logs and
  charcoal recursive cost.
- medicinal_plants: 0.20 farmer-days; 20 coins paid local harvest labor.

These are fictional production lots. No historical manufacturing claim is made.
No sale price is embedded in this module. Household prices use Economy.price.

GEOGRAPHY
fishery -> preserved_fish
timber -> fine_timber
agriculture -> medicinal_plants
refinery/trade -> lacquer
foundry/shipyard -> no regional production
Other industry strings -> no regional production

Every valid harbor can consume all four products.
Actual specialty derives from industry and is stored in regionalGoods.
Existing port.specialty remains untouched.

PRODUCTION AND PAYMENT

- One geographic product is considered per harbor per call.
- Workshop team is capped at four total workers, including specialists.
- Output is bounded by actual remaining worker-days, specialist-days, inputs,
  affordable payroll and space below a three-day local stock buffer.
- Input deductions occur only for the completed paid lot quantity.
- No product becomes an input to another simultaneous regional recipe.
- Paid harvest is the only recipe without purchased material inputs.
- Direct labor totals and worker-days come from Goods APIs.
- The occupation bills are checked against those APIs; inconsistent installed
  labor specs fail closed and produce nothing.
- Farmer/fisher/woodcutter work pays householdPurse.
- Carpenter/refiner and other expert-role work pays expertPurse.
- Both payments debit harbor cash through Money.move.
- Fractional purse-group bills round upward to integer coins.
- A bounded 48-step search reduces a batch when rounding prevents affordability.
- Transfers are first verified on small temporary balance dictionaries; failed
  payroll does not publish partial payments, stocks or worker reservations.
- Successful production decrements availability once and adds occupation-level
  worker capacity to employed.
- Money.move uses its default optional ledger. Regional records retain payroll
  and sales totals; there is no new persistent transaction ledger.

DEMAND AND OVERSUPPLY

Default whole-port optional need per day:
    min(12, workforce * 0.02)
This is a conservative workforce proxy because household/population counts
were not supplied as a guaranteed port field.

Need is divided equally among the four products.
Each product's workshop stock target is three days of that product's need.
Existing stock at/above target blocks further workshop production.

Household spending uses the purse remaining after the base tick and any
regional wages. Maximum spending per call is:
    floor(householdPurse * min(0.20, 0.08 * days))

Purchases require positive finite quotes, actual stock and integer coins.
Actual household coins move into harbor cash and actual lots leave stock.
Unavailable products do not expand the need for other products.
Unspent budget may remain; there is no forced full-budget expenditure.
Excess stock does not raise consumption and blocks future local production.
Essential food has already had priority in the required call order.

STATE AND VALIDATION

Persistent regionalGoods fields:
specialty
lastProduction
lastConsumption
lastWages
lastSpent
lastDays
lastNeed
lastWorkers
lastSpecialists
optional needLimit

Results describe the last completed valid call, including zero production/use.
report returns independent nested dictionaries and does not normalize state.
validate is read-only and returns an empty string on success.

Validation checks stocks, employed quantities, relevant purses, availability
and regional state for nonnegative finite values and valid shapes.
Whole-valued JSON floats are accepted for integer coin fields.
Unknown regional state fields and unknown regional product records are rejected.
Known stale specialty values are reconciled from actual industry by ensure.
Global stock keys remain open to other valid goods.

Safety bounds:
- Numeric state/stock values and individual purses: at most 1e12.
- Valid time step: finite, positive and at most 365 days.
- Invalid time steps and invalid input ports are no-ops in daily.
- Receiver purse capacity also bounds production/transfers.
- Quantities at/below 1e-7 are not traded or produced.
