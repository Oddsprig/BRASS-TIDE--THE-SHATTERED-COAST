2. EXACT PUBLIC APIs (game/scripts/expedition.gd, extends RefCounted)
Required contract static functions:
- static func traveling(state: Dictionary) -> Array
  Returns a new Array of boat Dictionaries from state.get("fleet", []) that are accompanying the expedition.
  Excludes any boat where:
  * boat.get("sunk", false) is true (or boat.hp <= 0.0 when hp is present)
  * boat.get("storedPort", "") (or stored_port / stored) is nonempty
  * boat.get("mothballed", false) is true
  * boat.get("crew", 0.0) <= 0.0 or boat.crew < max(1.0, boat.get("crewMin", boat.spec.get("crewMin", 1.0)))
  Places the flagship (state.get("flagship", "")) first when it is a valid traveling boat. Never mutates state or boat dictionaries.

- static func capacity(state: Dictionary) -> float
  Sums boat_capacity(boat) (max(0.0, float(boat.spec.cargo))) across traveling(state) only.
  Sunk, port-stored, mothballed, and under-minimum-crew hulls contribute 0.0 traveling capacity.

- static func cargo_weight(state: Dictionary) -> float
  Returns total physical weight occupying the traveling expedition's hold:
  commodity_weight(state) + freight_weight(state) + onboard_store_weight(state)
  where:
  * commodity_weight(state): sum over state.get("cargo", {}) of max(0.0, qty) * Goods.ITEMS[good].weight
  * freight_weight(state): sealed contract freight weight from state.get("freight", {}) (qty * Goods.ITEMS[good].weight; supports single Dictionary or Array of freight Dictionaries)
  * onboard_store_weight(state): sum over traveling(state) of boat_hold_store_weight(boat)

- static func report(state: Dictionary, world: Dictionary = {}, route_distance: float = 0.0) -> Dictionary
  Pure-data manifest and voyage readiness calculator. Never mutates state or world.
  Returns a Dictionary containing all required contract keys plus supporting breakdown fields:
  Required keys:
  * usableCapacity (float): capacity(state)
  * cargoWeight (float): cargo_weight(state)
  * freeCapacity (float): max(0.0, usableCapacity - cargoWeight)
  * overload (float): max(0.0, cargoWeight - usableCapacity)
  * crew (int): total crew aboard traveling(state) boats
  * dailyWages (int): crew * Goods.SAILOR_WAGE (100 bronze coins per sailor-day)
  * fuelDays (float): bottleneck fuel endurance in game days across traveling(state), with shared cargo reserve fuel (state.cargo.fuel) leveling up the lowest-endurance traveling boats first
  * foodDays (float): state.cargo.food / (crew * 0.08), or 0.0 when crew <= 0
  * repairKits (float): onboard traveling supplies + state.cargo.supplies (0.0 when traveling fleet is empty)
  * reserveDays (float): minimum return reserve in game days (max(1.0, oneWayDays * 1.25 + 0.5) when a route is given, 1.0 when idle in port with a traveling fleet, 0.0 when traveling fleet is empty)
  * affordableDays (float): max(0.0, coins - wageArrears) / dailyWages (0.0 when dailyWages <= 0)
  * tripDays (float): conservative round-trip estimate in game days ((2.0 * oneWayDays) * 1.25 * overload_factor + 0.5 when route_distance > 0 and cruisingSpeed > 0, else 0.0)
  * returnWages (int): ceil((tripDays if tripDays > 0 else reserveDays) * dailyWages) + wageArrears (0 when traveling fleet is empty)
  * warnings (Array[String]): human-readable readiness warnings for uncrewed/empty fleet, cargo overload, excluded capacity, tank/magazine overflow, fuel/food shortages, wage arrears/shortfalls, hull/engine/flooding/wound speed penalties, low repair kits, and >300 DP reserve split.

  Additional breakdown keys in report():

  * dailyFuel, dailyFood, minBoatFuelDays, enduranceDays
  * onboardRepairKits, reserveRepairKits, totalFuel, fuelTankCapacity, totalFood, totalAmmo, ammoCapacity
  * oneWayDays, cruisingSpeed, dailyDistance, routeDistance, roundTripDistance, contingency
  * ownedBoats, travelingBoats, storedBoats, mothballedBoats, undercrewedBoats
  * deployedBoats, reserveBoats, deploymentPoints, deploymentLimit (300), activeRosterCeiling (48)

3. FORMULAS AND LEGACY CAPACITY ASSUMPTION
- Once-Only Physical Storage & Legacy Capacity Assumption:
  In v0.001-v0.007, Damage.create_ship() and world.json START initialize every boat with fuel = 60.0 drums, ammo = 80.0 rounds, and supplies = 20.0 repair kits, even on light hulls whose spec.cargo is 45 (bilge_punt) or 60 (tin_skiff, with 30 starting food in state.cargo.food). Meanwhile, Harbor.resupply() and Harbor.use_reserves() define each boat's installed tank target as 60.0 drums (fuelCapacity) and installed magazine target as max(80.0, 80.0 * weaponMounts.size()) rounds (ammoCapacity).
  To reconcile physical storage without falsely overloading every newly created light hull from its built-in fuel tank:
  * Installed fuel tanks (default 60.0 drums/boat, overridable via spec.fuelCapacity) and installed weapon magazines (default 80.0 rounds/mount, overridable via spec.ammoCapacity) are treated as dedicated hull compartments. Working fuel and ready rounds within those installed limits occupy their tank/magazine once without consuming dry-cargo hold space (spec.cargo).
  * Onboard repair kits (boat.supplies, 1.0 ton/kit) have no separate tank/magazine compartment and always occupy general hold space once, whether stored in state.cargo.supplies or loaded into boat.supplies via Harbor.use_reserves(). Consequently, calling Harbor.use_reserves() to move repair kits from state.cargo.supplies to boat.supplies conserves cargo_weight(state) 1:1.
  * Any onboard boat.fuel exceeding boat_tank_limit(boat) (1.0 ton/drum) or boat.ammo exceeding boat_magazine_limit(boat) (1.0 ton per 50-round case) overflows into general hold space (cargo_weight) once and emits a warning.
  * On the v0.007 starter state (Tinwake Skiff, spec.cargo = 60, food = 30, boat.supplies = 20, boat.fuel = 60, boat.ammo = 80), cargo_weight is 30 + 20 = 50.0 tons, leaving 10.0 free capacity (sufficient for the 8-ton side delivery contract). However, a legacy save that previously filled state.cargo to 100% of spec.cargo while also carrying 20 onboard repair kits (or relying on mothballed boats for hold capacity) will show overload > 0.0 in v0.008 until excess cargo is sold, stored, or consumed.
- Fuel Consumption & Fleet Minima:
  * Per-boat underway fuel burn matches campaign.gd:234 and DAY_SECONDS = 45.0:
    boat_daily_fuel(boat) = 45.0 * (0.011 + size * 0.0002) * max(0.2, fuelUse)
    where fuelUse is read from boat.spec.fuelUse (or resolved from boat.loadout.engine in Refits.catalog().engines).
  * Because any single traveling boat running out of fuel drops fleet speed to 0.3x in campaign.gd:186, fuelDays uses the bottleneck minimum across traveling(state). When state.cargo.fuel > 0, reserve fuel drums level up the lowest-endurance traveling boats first (water-filling allocation).
- Food Consumption:
  * Matches economy.gd and fleet_economy.gd: dailyFood = crew * 0.08 bales/day; foodDays = state.cargo.food / dailyFood.
- Cruising Speed & Conservative Trip Estimate:
  * Per-boat speed matches campaign.gd:186:
    boat_speed = spec.speed * morale_factor_if_unapplied * max(0.25, Damage.get_status(boat).speedFactor) * (1.0 if boat.fuel > 0 else 0.3)
  * Fleet cruisingSpeed = min_{boat in traveling}(boat_speed) * 1.55 * campaign_scale.
  * Daily distance = cruisingSpeed * 45.0.
  * If route_distance <= 0.0 and state.path is non-empty, routeDistance is computed along state.position -> state.path.
  * oneWayDays = routeDistance / dailyDistance.
  * tripDays = (2.0 * oneWayDays) * 1.25 * overload_factor + 0.5 (25% contingency + 0.5 day turnaround buffer, scaled up by up to 50% if overloaded).
  * reserveDays = max(1.0, oneWayDays * 1.25 * overload_factor + 0.5) when routeDistance > 0, or 1.0 when routeDistance == 0 and traveling fleet is non-empty.
