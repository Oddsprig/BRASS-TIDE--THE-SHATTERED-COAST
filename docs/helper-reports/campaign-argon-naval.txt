2. EXACT PUBLIC APIs (game/scripts/naval_ai.gd, extends RefCounted)
Required contract static functions:
- static func ensure(state: Dictionary, _world: Dictionary = {}) -> Dictionary
  * Callable as NavalAI.ensure(state) (single argument) or NavalAI.ensure(state, world).
  * Normalizes all NPC owners in state.get("fleetOwners", []) via Fleets.normalize_owner(owner), records initial targetBoats and preferredHulls per owner, initializes state["navalAi"] (version, tickCount, lastDay, encounters, replacements, spatialGrid, ordersByOwner), ensures every owner has a populated owner["order"] dictionary with purpose, destination, reason, reserves, and performance, and builds the spatial patrol grid.
  * Syncs a lightweight _navalAiCache on state.fleetOwners[0] so encounters, replacements, and tickCount survive Campaign.restore(saved) JSON round-trips even before campaign.gd adds "navalAi" to new_game() top-level keys.

- static func arrived(core, owner: Dictionary, dock: Dictionary = {}) -> String
  * Accepts either a Campaign instance (core.state / core.data) or a raw state Dictionary.
  * Evaluates the NPC owner's actual fleet condition and returns the next target port ID String (always a valid port ID in state.ports, distinct from dock.id whenever state.ports.size() > 1).
  * Updates owner["order"] (and bounded owner["orders"] history, max 8) with:
    - purpose: "deliver" | "escort" | "intercept" | "patrol" | "raid" | "withdraw" | "repair" | "resupply" | "replace" | "blockade"
    - destination: next target port ID
    - targetOwnerId: target convoy or raider owner ID when escorting, intercepting, or raiding
    - reason: human-readable causal explanation with port/convoy/commodity details
    - reserves: fleet_reserves(owner) (coins, crewPurse, wageArrears, crew, ableCrew, minCrew, boats, targetBoats, hpRatio, minEngine, fuel, fuelDays, food, foodDays, ammo, supplies, wageDays, tradeCargo, capacity)
    - performance: fleet_performance(owner) (performanceFactor, morale, speed, firepower, seaworthy)
    - flat convenience keys on order: coins, crew, boats, hpRatio, fuel, food, ammo, supplies, speed, firepower, performanceFactor, morale
  * Role & condition routing:
    - Story blockade owners (id begins with "story-"): keep purpose = "blockade" at their mission targetPort.
    - Damaged / under-strength / low-store fleets (living boats < targetBoats, crew < crewMin, active breaches/fire/flooding, hpRatio < 0.65, minEngine < 0.68, ammo < 18/boat, or fuel < 0.6/boat):
      * If docked at a foreign port (dock.id != owner.homePort), orders return to owner.homePort with purpose "replace" / "repair" / "resupply".
      * If already at owner.homePort, runs Fleets.dock(owner, dock_port) and attempts request_replacement(core, owner, dock_port) if below targetBoats.
    - Traders (kind == "trader"):
      * When empty away from homePort, return to homePort ("resupply") to load export stock.
      * When loaded (or after loading at homePort), score all non-hostile ports by actual sell price (Economy.price(p, good, "sell")), scarcity gap ((equilibrium - stock) / equilibrium), buyer cash liquidity, unit margin, and distance, selecting the best demand port with purpose = "deliver".
    - Patrols (kind == "patrol"):
      * First prioritize intercepting active non-story raiders near friendly lanes/ports (purpose = "intercept", targetOwnerId = raider.id).
      * Otherwise escort active loaded trader convoys along their trade lane (purpose = "escort", targetOwnerId = trader.id), falling back to coastal lane patrol ("patrol").
    - Raiders (kind == "raider", non-story):
      * Seek active loaded trader convoys weighted by cargo value (tradeCargo * Goods.cost(tradeGood)), owner coins, and distance (purpose = "raid", targetOwnerId = convoy.id).

- static func tick(core, days = 1) -> Array
  * Advances autonomous naval AI by integer day steps and returns an Array of up to 24 human-readable event strings.
  * Step 1: Advances any unstepped NPC slip orders in port.buildQueue (when caller did not already step them via Harbor.tick_yards that day) and collects ready orders (order.ready == true and order.escrow == 0) via collect_replacements(core).
  * Step 2: Checks under-strength non-story owners at harbor/homePort and requests replacement via request_replacement(core, owner, port).
  * Step 3: Finds spatially nearby hostile NPC chart patrols via nearby_hostile_pairs(state, ENCOUNTER_RADIUS) using a 240 px spatial grid (never comparing all pairs or touching "story-" owners), and resolves up to MAX_ENCOUNTERS_PER_DAY (4) bounded pair skirmishes per day via resolve_encounter(...).
  * Step 4: Refreshes owner orders, reserves, performance, patrol.active flags, and spatial index.

3. KEY MECHANICS, CONSERVATION GUARANTEES & CAVEATS
- Spatial Lookup & Story-Owner Protection:
  * spatial_index(state, 240.0) buckets active non-story chart patrols by 240x240 world cells and inspects only the 3x3 neighborhood around each patrol.
  * Any owner or patrol whose id begins with "story-" is strictly excluded from spatial indexing, automatic pair encounters, and automatic replacement so story blockade detachments are never artificially removed or depleted before player missions.
  * When a patrol and a trader are both near a hostile raider, pair priority sorts patrol-vs-raider interception ahead of trader-vs-raider.
- Seeded Bounded Skirmish Resolution:
  * Uses a local RandomNumberGenerator seeded deterministically from state.seed, state.econDay, and the pair ID hash (never global RNG or randomize()).
  * Runs up to 5 salvos (5.5s each) using each living boat's actual weaponMounts (or spec weapon), Damage.get_status(boat).weaponFactor, owner.performanceFactor, and actual boat.ammo.
  * Each hit calls Damage.apply_hit(target, hit, rng) and each salvo ticks Damage.tick_ship(boat, 5.5, {"inCombat": true}), followed by an 8.0s post-skirmish repair-policy damage control pass consuming actual boat.supplies.
  * Sides withdraw early when a hull is lost, ammo is exhausted, hpRatio < 0.56, minEngine < 0.52, or a trader takes heavy fire against a stronger raider; withdrawing fleets switch order to "withdraw" toward homePort and reverse patrol course if heading away from homePort.
  * Prize coins (10% on forced retreat, 25% on wipeout) transfer via Money.move(loser, "coins", winner, "coins", ...), and captured tradeCargo transfers within winner free hold capacity.
- Funded Hull Replacement & Global Coin Conservation:
  * One replacement per owner at a time (_owner_has_queued_replacement scans all ports' buildQueue for order.npcOwnerId == owner.id).
  * Port buildQueue limit of 2 slips (MAX_SLIPS_PER_PORT = 2) is strictly enforced.
  * Ready Stock Path: requires port.shipStock[hull] >= 1, available port recruits/workforce >= crewMin, and owner.coins >= q.readyPrice + Economy.recruit_cost(port, crew). Transfers q.readyPrice - tax to port.cash and tax to port.governmentPurse via Money.move, decrements port.shipStock, recruits finite crew via Economy.recruit (moving advance from owner.coins to owner.crewPurse and decrementing port.recruits and port.workforce), initializes the hull with zero stores (fuel = 0, ammo = 0, supplies = 0), and calls Fleets.dock(owner, port) to buy working stores from port.stocks.
  * Slip Commission Path: when shipStock is 0, requires hull in port.shipIds, buildQueue.size() < 2, port.stocks >= q.materials, and owner.coins >= q.commissionPrice. Creates order via Construction.make_order(h, q, "yard") (keeping order.owner == "yard" so SaveValidation._order passes without schema conflict) and sets order.npcOwnerId = owner.id and order.fundingSource = "npc". Consumes q.materials from port.stocks, moves commissionPrice - escrow - tax to port.cash, moves tax to port.governmentPurse, moves wage escrow from owner.coins into order.escrow, and appends order to port.buildQueue. All coins remain counted by Money.total(state) at every step.
  * Collection Path: when order.ready == true and order.escrow == 0 on the slip, collect_replacements recruits crew via Economy.recruit, attaches the hull with zero initial stores, runs Fleets.dock(owner, port) to purchase working stores, and removes the order from port.buildQueue.
- Root Integration Seams:
  * In harbor.gd tick_yards(core, days): when an order transitions to ready, check `if order.get("owner", "player") == "yard" and str(order.get("npcOwnerId", "")).is_empty():` so NPC replacement orders remain on p.buildQueue for NavalAI.tick to collect rather than incrementing p.shipStock.
  * In campaign.gd: call NavalAI.ensure(state, data) in new_game() and restore(), call NavalAI.arrived(self, owner, b) when a chart patrol reaches p.progress >= 1.0 in step(dt) and rebuild patrol course via set_patrol_course(p, b, port(next_id)), and call NavalAI.tick(self, 1) in apply_economy().
