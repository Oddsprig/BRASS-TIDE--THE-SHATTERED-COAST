PUBLIC API (game/scripts/exploration.gd, extends RefCounted, all static)
- ensure(state: Dictionary, world: Dictionary = {}) -> Dictionary
  Creates/normalizes state["exploration"] and returns that sub-state:
  {version:1, catalog:Array, sites:{siteId:{level:int, rewarded:bool}},
   assignment:Dictionary, leads:Array, log:Array}. All plain JSON types.
  Catalog priority: world["ISLAND_SITES"] if root supplies it, else
  res://data/island_sites.json read once (static cache, never per tick),
  else a built-in fallback copy of the same authored sites. The resolved
  catalog is copied into state so a save keeps stable site identities even
  if the data file changes later. Progress for unknown ids is dropped and
  levels are clamped to 0..3. Safe to call on legacy saves without the key.
- sites(state: Dictionary) -> Array
  Every catalog site merged with progress, sorted by id, deep copies.
  Fields: id,name,x,y,kind,region,clue,discovery,hazard,resource,leadId,
  level (0 unknown, 1 sighted, 2 charted, 3 surveyed), levelName, rewarded.
- discover_near(state: Dictionary, position, radius) -> Array
  position may be {x,y}, Vector2 or [x,y]. Sights (level 1) every unknown
  site within radius and returns only the newly sighted merged sites.
  Invalid position/radius and repeat sightings return []. Never downgrades.
- quote(state: Dictionary, site_id: String, action) -> Dictionary
  action "chart" (sighted->charted, aliases coastal_chart/chart_coast) or
  "survey" (charted->surveyed, aliases landed_survey/deep_survey).
  Read-only apart from ensure(). Returns ok, siteId, siteName, action,
  level/levelName, targetLevel, crewNeeded, spareCrew, days, food, supplies,
  haveFood, haveSupplies, hazard, resource, message. Refuses unknown
  site/action, wrong starting level, already-at-target (repeat), a running
  assignment, insufficient spare crew, food or supply kits.
- begin(state: Dictionary, site_id: String, action) -> Dictionary
  Returns the refused quote unchanged when not ok (consumes nothing). On
  success consumes the quoted state.cargo food and supplies exactly once,
  clamps cargo at zero, and stores the single assignment:
  {siteId, action, targetLevel, crewReserved, daysTotal, daysDone,
   foodSpent, suppliesSpent}. Boat crew numbers are NOT mutated; the
  reservation is a record for root's crew-availability integration.
- advance(state: Dictionary, days) -> Array
  Adds game days to the active assignment. Returns [] for no/invalid/
  partial progress. On completion clears the assignment, raises the site
  level exactly once, and returns one event:
  {kind:"survey_complete", siteId, siteName, level, levelName, discovery,
   resource, leadId, lead}. A surveyed site sets rewarded=true once.
  Leads are appended once per from->to pair as
  {id:"from->to", fromSite, toSite, kind, resource, claimed:false}.
- spare_crew(state: Dictionary) -> int
  Sum over living, non-mothballed boats with empty storedPort of
  max(0, crew - crewMin). Sunk/mothballed/port-stored boats give nobody.
- assignment(state: Dictionary) -> Dictionary  (convenience, deep copy)
- catalog_site(state: Dictionary, site_id: String) -> Dictionary (raw entry)

FORMULAS AND CONSTANTS (from existing source, nothing invented silently)
- Food: existing campaign equation in economy.gd daily_upkeep is
  0.08 food per living crew per day (DAILY_FOOD_PER_PERSON, tested at
  5 crew = 0.40/day). Quote food = snappedf(0.08 * crewNeeded * days, 0.01).
- Wages: none moved. Assigned sailors are already paid through the existing
  100 coins/sailor-day daily upkeep on the whole fleet; charging wages here
  too would double-pay. Coins are never read or written by this module.
- Action table (new tuning, root may rebalance in ACTIONS):
  chart  = 2 spare crew, 1.0 day,  1 cargo "supplies" kit, 0.16 food.
  survey = 4 spare crew, 2.5 days, 2 cargo "supplies" kits, 0.80 food.
  "supplies" is the existing goods.gd Drydock & Repair Kits good, used here
  as survey/landing equipment. No new good was invented.
- Findings grant knowledge/opportunity only: resource names an existing
  goods.gd id (food, timber, saltpeter, ore, crude, sulfur, supplies) or
  "route"/"workshop"/"" for non-stock findings. No coins, goods, boats or
  crew are created on completion; harvesting/recovery is root's later work.

CATALOG (game/data/island_sites.json, fields id,name,x,y,kind,region,clue,
discovery,hazard,resource,leadId)
14 original sites in open water beside varied existing islands/coasts of the
10400x7200 world: Lantern Freshwater Cove, Kelpback Shoal Cut, Kelpback Toll
Camp, Sawtooth Ironwood Stand, Verdigris Salt Pans, Middle Marsh Landing,
Cinder Crown Ore Seam, Cinder Crown Workshop Ruin, Kettle Fen Sheltered
Inlet, Oilstone Seep Terrace, Naphtha Sulfur Vents, Middle Sea Chart Rock,
Rust Salvage Anchorage, Shatter Wreck Field. Coordinates were placed outside
every island polygon in world.json by inspection; the test file asserts
Navigation.is_water for each site so root's serialized run proves it.
Kinds cover the roadmap's first discoveries: freshwater cove, shoal shortcut,
defended camp, timber stand, salt seam, marsh landing, ore seam, workshop
ruin, sheltered inlet, oil seep, sulfur vents, chart fragment, salvage
anchorage and wreck field. Several leadId values chain sites together.

INTEGRATION NEEDS FOR ROOT (v0.009, intentionally not done here)
- campaign.gd: call Exploration.ensure(state, data) in new_game/restore,
  call discover_near on movement/arrival with a chosen sight radius
  (proximity gate is root's), and advance(state, days) beside the existing
  daily economy step. Optionally expose world ISLAND_SITES if root prefers
  loading the JSON itself; otherwise the module loads it once.
- Crew: while assignment.crewReserved > 0, root should treat that many
  sailors as ashore for boat-minimum/autopilot purposes if desired; this
  module only guarantees they exist above boat minimums at begin() time.
  If boats sink or crew are lost mid-assignment, root decides whether to
  cancel; advance() will still settle the recorded assignment once.
- UI/chart: draw sites by levelName; show clue at sighted, hazard/approach
  at charted, discovery/resource/lead at surveyed. Act on leads and on
  resource/route/workshop findings (shortcuts, harvest nodes, wreck
  recovery in v0.010) in root systems.
- Save validation: state["exploration"] is a new optional top-level key of
  plain JSON types; add it to save_validation.gd when integrating. Legacy
  saves without it migrate by ensure() with no other field touched.

CAVEATS / KNOWN SHORTCOMINGS
- Site water placement is asserted by the unrun test, not yet proven by an
  engine run in this report.
- Durations/crew/kit costs are first-pass tuning constants in one table.
- begin() trusts state.fleet crew/crewMin/sunk/mothballed/storedPort field
  names as used by campaign.gd active_fleet()/damage ships; boats missing
  those fields count as 0 crew rather than erroring.
- Multiple assignments are refused by design (one survey party); queueing
  beyond one, specialists/surveyor quality, weather and hazard resolution
  are future root work, as are all chart/UI/combat hooks.
