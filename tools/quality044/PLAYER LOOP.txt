THE PLAYER LOOP
Commit to a firing pass. Read each fitted weapon's remaining reload and actual
fire restriction. Break away with the existing move/withdraw/manual controls
while reloading. Read whether water is rising or draining and whether engine,
fuel, repair hands and kits remain. Use the existing flagship crew priorities
to bail or patch, then choose when to return. No new pressure bar, recovery
cooldown, damage value, ammunition pool, screen or automatic re-entry gate.
The short existing damage-control hint now states this loop and clarifies
that its crew-priority buttons act on the FLAGSHIP.

WHAT CHANGES IN THE CURRENT HUD
The same right-side intent Label names SELECTED plus the actual first living
owned selected boat. For multiple selected boats it says '(1 of N)'; values
belong to that named boat, not a group aggregate or an implicit flagship.
Enemy, sunk, secured-prize, stale and repeated IDs do not inflate that count.
An empty valid selection clears prior text. Existing intent, target, physical
mount order/identity and aim/lane/automatic-fire restriction messages remain.
The existing flagship bars, damage text and policy callbacks remain intact.
No additional widget is allocated. The intent Label already wraps words and
its existing right-side container already scrolls.

Readiness adds three short lines, and a fire line only when fire is nonzero:
  Water <current percent> - rising / draining <current L/s>, steady, or dry.
  Engine <actual condition percent> [disabled] - actual fuel, or NO FUEL.
  Repair <currently assigned hands> - actual kits, or NO KITS.
  Fire <current percent> when relevant.
These are current projections, not a prediction that the boat can safely
return or that supplies/crew will last a future engagement.

SOURCE CONTRACTS
CombatPressureView.selection returns a synchronous borrowed live boat reference
plus the distinct valid selection count. Callers must only read that reference.
readiness(boat, flow) returns fresh text from the current boat and the existing
Damage.get_status_cached projection on battle.tactical.damageCache. A miss
uses Damage's existing full public validation; no snapshot stored on a boat,
no new cache, no weakened equipment guard, no delayed state invalidation.
An invalid equipment projection reads 'Damage control unavailable'.

Water trend = flow.inflow minus flow.bailing. Bailing already includes real
hands and pumps. Dry boats do not show fictional negative water. Engine uses
flow.engineHp AND flow.engineFactor, so nonzero HP on a disabled engine is
not described as working. Fuel is separate. Repair uses flow.crewRepair and
boat.supplies; it does not call the projected patch capacity actual completed
work or promise a repair deadline. Crew can still bail and fight fire with
no kits; NO KITS refers to patch/hull/machinery repair material readiness.

weapon_state reads the current fitted mount and existing EquipmentCombat
mount_factor with the supplied current status. Disabled equipment, insufficient
real ammo for mount.ammoCost and unavailable gun crew cannot read Loaded.
Remaining reload is boat.weaponCooldowns[index], with the real primary timer
maxed against boat.cooldown, exactly as the Battle compatibility path requires.
Missing secondary timing reads 'Reload unavailable', never a generated zero.
Positive timers show seconds; at zero, 'Loaded' proves reload completion only.
The existing lane/aim/hold/reserve/manual reason stays visible. A stale prior
'Reloading' reason becomes 'Loaded - waiting for shot'. No new shot permission,
reserve calculation, salvo reset or firing decision is introduced.
All numeric quantities use existing Damage.number and the existing canonical
condition adapter; there are no newly tuned thresholds or balance parameters.
