052 LOGISTICS REPORT CONTRACT - baseline 92a5e58 - source only

API: Expedition.report(state, world, route_distance=0.0, actual_speed=-1.0).
Campaign.expedition_report(distance) passes travel_speed() as the optional last
argument. Existing three-argument callers and every legacy report key remain.
All route-dependent numbers/warnings use that same speed. Legacy direct calls
derive the same damage/towing speed model. tripDays is outward
+ return + reserveDays (2). No chart_course/payment/state changes.

Added flat fields (numbers unless noted): routeDistance, routeSpeed, outwardDays,
returnDays; foodPerDay, foodAvailable, foodRequired, foodShortfall; fuelRequired,
fuelShortfall, looseFuel; wageArrears, fundsAfterArrears, wageShortfall;
payloadAfterFood, allowanceOverload; ownedCount, travelingCount, storedCount,
inactiveCount, ownedDP, activeDP, battleDP, battleLimit (300), battleReserveCount;
readyForAllowance (bool), bottleneck (String), boats (Array), supportOptions (Array).
wageShortfall includes unpaid existing arrears plus projected returnWages versus
the captain's actual coins; stored sailors and specialist premiums remain paid.
Food uses Economy.daily_upkeep, including actual fitted food efficiencies.
payloadAfterFood is hold room after missing food, BEFORE fuel loading; no loose
fuel is counted as loaded or support credited as shared tank capacity.
Counts/ownedDP cover the player's nonsunk state.fleet (not company fleets or
unresolved boarding prizes); inactiveCount includes stored hulls. activeDP is
all traveling DP, battleDP/battleReserveCount use Deployment.split in actual
flagship-first order. Ownership and support can exceed the 300 battle limit.

boats entries: uid/name (String), fuelPerDay, loadedFuel, tankCapacity, loadedDays,
tankDays, fuelRequired, fuelShortfall, tankShortfall. All are per actual traveling
boat. tankShortfall is requirement beyond the physical tank; existing loaded
overflow stays real cargo. fuelShortfall sums actual boat shortages, not reserves.

supportOptions entries are owned inactive, nonsunk hull projections ONLY;
each includes every boats entry field plus storedPort (String), addedCapacity,
crewToMinimum, additionalDailyWages, additionalFoodPerDay, blockers (Array),
projectionOnly=true. Added wages/food count only missing minimum crew: existing
owned sailors are already in dailyWages/foodPerDay. Fuel allowance uses CURRENT
route speed; activating a slower hull requires recalculating the report. Nothing
is moved, hired, repaired, fueled or purchased. New purchases use existing real
Harbor.quote/catalogue or campaign_guidance outside this pure report.

Readiness covers traveling hulls, hold/food, loaded boat fuel and actual purse;
low repair stock is an advisory warning. It is an allowance preview, not a new
sailing permission or a promise against encounters. Distances are supplied by
the existing caller; no new route planner. Tests prepared by proof peer, NOT RUN.
