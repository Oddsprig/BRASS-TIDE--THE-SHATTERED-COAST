RUNTIME API (main thread, between draws)

Chart instance:
  chart.profile_enable(true)  # toggle only; does not reset or warm anything
  chart.profile_reset()       # measurements only; caches and wakes stay live
  # Read after the existing RenderingServer.frame_post_draw boundary:
  var sample: Dictionary = chart.profile_read()
  chart.profile_enable(false) # retain the last measurements for reading

profile_enable(enabled: bool=true), profile_reset(), profile_read()->Dictionary
also exist on BoatArt.MeshCache and CombatArt. Chart forwards enable/reset to
both, so Runtime needs no new preload. Counters default to disabled. Enabling
does not request redraws, launch a battle or change any rendering option.

Chart read schema:
  enabled: bool
  draws: int, completed measured Chart._draw calls since reset
  last_frame: Dictionary, latest measured Chart draw; empty until first draw
  mesh_cache: Dictionary, process-wide cumulative counters since reset
  combat_art: Dictionary, process-wide cumulative counters since reset

The returned dictionaries contain copied scalar measurements, no live boats,
effects, meshes or callbacks. Reading does not consume or reset counters. Check
draws/last_frame.draw for freshness; disabled draws retain the previous sample.
Static counters include other users of these scripts in the same process,
including portraits. One active Chart/profile owner is assumed. Take differences
of cumulative counters between samples; do not reset the cache per frame.

LAST_FRAME COUNTERS

  draw, mode, viewport_width, viewport_height, scale_factor, tactical
  presentation_us: reuses existing whole Chart CPU draw-submission measurement
  boats_total: battle.ships size, including sunk entries
  boats_live: nonsunk entries in the unchanged sorted drawing loop
  boats_visible: accepted by the existing conservative boat culling margin
  boat_centers_on_screen: accepted boats whose projected origin is in viewport
  boats_culled / boats_invalid: existing cull/spec rejection paths
  authored_hulls: successful authored-hull draws among boats_visible
  boat_sprites: existing BoatArt sprites return, hull and fitted weapon layers
  boat_primitives: existing BoatArt primitives return
  lod0 / lod1 / lod2: counts at the unchanged chosen boat LOD
  boats_us: whole boat loop, including culls, bars, prize labels/order indicators
  sort_us: existing shallow ship-array copy plus identical depth sort
  wake_updates: calls to the existing wake update since the previous draw
  wake_update_us / trail_update_us: CPU update totals since the previous draw
  wake_draw_us / trail_draw_us: existing draw functions including their culling
  wake_paths / wake_samples: accepted wake paths and samples offered to BoatArt
  wake_primitives / trail_primitives: existing draw return values
  projectiles_total / projectile_primitives / projectiles_us: whole unchanged loop
  effects_total / effects_submitted / effect_primitives / effects_us
  wrecks_total / wrecks_submitted / wreck_primitives / wrecks_us
  counted_primitives: sum of the six boat/wake/trail/projectile/effect/wreck counts

Effects/wrecks submitted means the existing conservative cull accepted them;
the draw return may still be zero. Wreck timing includes the existing sinking
count and coarse-copy path. Wake samples can include older samples rejected
inside BoatArt's unchanged short foam-life filter. Timing does not extend life.

Visibility is conservative draw eligibility, not a pixel/occlusion query.
Primitive counts are logical canvas submissions: a cached mesh or sprite counts
as one, not its triangles. counted_primitives excludes terrain, cheap water,
selection rings, bars, labels, minimap, fort/boarding drawings and external UI.
boat_sprites counts live Chart boats; wreck FadeCanvas has no texture support.
These counters are not complete RenderingServer draw-call/GPU-primitive totals.

MESH_CACHE COUNTERS

  enabled, hits, misses, build_us, build_max_us, evictions, clears, entries

hits/misses count measured draws only; the original public hits/misses retain
their existing always-on behavior. build_us sums synchronous miss construction:
Capture creation, existing bake callback, eviction, mesh/resource construction,
cache insertion and order append. It excludes key construction and GPU completion.
build_max_us is the largest measured miss since reset. entries is the current
cache-size gauge. clear() retains its old semantics and only increments clears
while profiling; profile_reset() never invokes clear(). A mid-window clear is
visible without making cumulative profile hits/misses negative.

COMBAT_ART COUNTERS

  enabled, triangulation_calls, triangulation_us, triangulation_max_us,
  triangulation_rejected

Time only the existing explicit Geometry2D.triangulate_polygon validation in
_fx_poly and FadeCanvas.draw_colored_polygon. Each original guard still performs
one identical triangulation and uses its result, including when profiling is
disabled. This covers effects and wreck/faded-hull validation together. It does
not cover BoatArt wake/hull validation, mesh Capture triangulation, or internal
CanvasItem/renderer triangulation. It is nested within effect/wreck CPU timing;
do not add overlapping totals as independent frame costs.
