EARLY API CONTRACT FOR ROOT / B / C
Factions.commission_terms(state, faction_id) -> Dictionary
  Read-only, detached terms query. Requires existing Factions.ensure data;
  never calls ensure, writes pending, signs, applies standing, or changes coins.
  Returns ok/message, factionId/factionName, eligible, committed, changed=false,
  repeated=false, explicit=false, stipend=0, legalShift=-12, enemies (IDs),
  enemyNames, warning, and contract (deep copy, empty if no matching commission).
  Eligibility and enemy lists reflect current public/witnessed standing/pairs.
  Saved legacy pending flags have no effect on this query or actual UI review.

Factions.accept_commission(state, faction_id) -> Dictionary
  Explicit consent operation, independent of legacy pending. Rechecks current
  eligibility/enemies before signing; preserves existing -12 legal-event keys,
  repeat behavior, zero stipend/reward/escrow and existing commission storage.
  A repeated matching commission does not reapply legal shifts or mint money.
  Neither operation introduces another contract or payment backend.

Factions.commission(state, faction_id) remains the legacy two-call API for
old callers/reference checks. Actual UI reviews use commission_terms only;
only the Accept button invokes accept_commission. No B/C caller changes needed.
Faction UI uses existing faction names/colors, descriptions and doctrine text.
Friendly/trusted/claim access reasons no longer advertise unimplemented escort,
intelligence or repair-priority services. Access flags and permissions remain
unchanged; claim text reflects the actual Politics repair-yard restriction.

IMPLEMENTED UI / MUTATION BOUNDARY
Review and Back never call the legacy commission API or write pending flags.
The modal's ordinary close path likewise has no commission mutation to finish.
Only an eligible unrecorded commission shows Accept. The button re-queries
current enemies; a changed list refreshes terms for another explicit click.
Acceptance re-queries current eligibility and enemies itself. Current patron,
actual enemy names, the original -12 public shift, possible access/patrol
consequences and no stipend are shown before consent. Reopening a saved legacy
pending commission is harmless. The old commission(state, faction_id) behavior
is deliberately retained for old callers, including its two-call pending path;
it must not be used to implement a review UI.
