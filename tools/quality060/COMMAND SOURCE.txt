EXACT IMPLEMENTED SHARED CONTRACT - FOR ROOT TO RELAY TO C
1. boat.commandPreference is OPTIONAL {"doctrine": String, "role": String}.
   Allowed doctrine: cautious / steady / aggressive. Allowed role: auto /
   skirmisher / striker / heavy / screen / support. Missing field reads as
   steady/auto; save validation accepts absence and rejects malformed/extra
   keys. Stored on the physical campaign boat by uid, never battle id.
2. FleetIdentity.command_preference(boat: Dictionary) -> Dictionary
   returns a detached canonical {doctrine,role}, without changing boat.
3. FleetIdentity.set_command_preference(core, uid: String, doctrine: String,
   role: String) -> Dictionary. Explicit action, validates the owned living
   boat and both values before changing ONLY that boat.commandPreference.
   Success: {ok:true,message,boatUid,commandPreference:{doctrine,role}}.
   Failure: {ok:false,message}. No economy sync, ensure, hiring or spec change.
   Intent applies at NEXT tactical registration. Existing battle orders win.
4. FleetSupport.selected_view(c, uid: String) -> Dictionary.
   Pure read; returns {ok:false,message} for missing boat. Success fields:
   ok, boatUid, name, commandPreference, crew, morale, payroll, staff, hiring,
   fittedSpec, effectiveSpec, service, serviceHistory.
   crew = {aboard,wounded,ashore,able,minimum,optimal,maximum} (numbers).
   morale = {value,factor}; factor = clamp(value/85,0.35,1).
   payroll = {basePerSailorDay:100,basePerDay,premiumPerDay,totalPerDay,
     fleetBaseArrears,boatPremiumArrears,fleetCrewPurse}.
   BasePerDay includes every living sailor aboard this hull, specialists too;
   base arrears and aggregate crew purse are explicitly FLEET accounts.
   staff = detached current assigned, nonlost/nondischarged records with:
     id,name,role,roleName,active,effect,effects,advance,premiumPerDay,
     basePerDay:100,totalPerDay,coins,arrears.
   active requires actual hired record+paid flag, no premium/base arrears and
   a living crew berth. effects is the actual paid multiplier/addition map,
   empty when inactive. effect is a truthful human-readable status/effect.
   advance is the CURRENT local replacement/hiring advance, not a fabricated
   historical receipt; 0 at sea. premium purse remains staff[].coins.
   hiring = one detached row per existing specialist role:
     role,roleName,advance,basePerDay:100,premiumPerDay,totalPerDay,
     eligible,message,qualification.
   eligibility uses the SAME gates as the explicit hire transaction. Qualified
   gunner/mechanic is consumed if present, otherwise existing sailor fallback;
   no newly mandatory professional course. Current local permission is checked
   once against a copied state using existing FleetWorkshop.PermissionView.
   Review never live-ensures/reconciles, pays, advances time or constructs
   Campaign/world/navigation. fittedSpec is canonical current paid loadout;
   effectiveSpec is detached actual boat.spec including current paid effects
   and morale. service/serviceHistory are detached existing values.
   Low-level common quote: FleetIdentity.specialist_quote(state: Dictionary,
   boat: Dictionary, port: Dictionary, role: String, permission: Dictionary)
   -> Dictionary, the same hiring row. C uses selected_view; the explicit hire
   revalidates current permission and this quote before the existing payment.
5. Existing FleetIdentity.hire_specialist / FleetSupport.dismiss remain the
   paid explicit actions. No new professional, purse or qualification model.
6. TacticalRuntime.register seeds ONLY doctrine/role into previously absent
   options for a player boat with a real uid. Other defaults stay fresh. A
   repeated register does not override any later player options. No saved
   arena ids, targets, rally points, formations or physical mount holds.
