INTERFACE FOR ROOT / PROOF SOL

Ordinary/default/one-argument legacy planning retains its eager per-begin
observations and existing private current-begin/retained/wait-helper contracts.

For N active t.ships at a sampled begin, the unconditional owner/order/mount
loop now makes ZERO _observed calls. Each actual _view051 request rebuilds N
full base observations from current owners and refreshed mounts. Thus each
actual sampled SIDE dispatch makes N _observed calls and one view call;
two actual SIDE dispatches make 2*N, with separate detached inputs. A sampled
tick with no dispatch and no explicit view request makes ZERO _observed calls.
An explicit public view(st,side,due) in sampled mode also makes exactly N
_observed calls, enriches ALL friendly owners, and detaches every returned
nested record. It always rebuilds, including repeated requests at the same
clock after live input changes. No previous sample is reused or relabeled.
Direct _worker_view051 requests have the same N-call demand semantics.
These counts use the existing opt-in counters; no new profiler is added.
Each sampled begin clears t.observed; it stays empty if no snapshot is requested.
A demand rebuild populates that internal observation table until the next begin,
but the next request always replaces it rather than relying on that lifetime.
Preparing this table grants no decision/adoption/safety timestamps or authority.

Expected regressions to preserve/add in Root's test lane: skipped cadence,
occupied SIDE and global task-cap refusals build no views; dispatched samples
contain current poses, time/revision, shot/cooldown state, equipment, commands,
options and targetless attack's current nearest hostile; subsequent owner,
mount, order/options or shot-time mutations cannot change a retained capsule.
Public full snapshots remain fresh and mutable without changing live inputs.
Retain existing owner/order/terrain/capability/age, traffic, post-motion shot,
damage, fuel/crew/stores/coins/RNG and legacy parity assertions. No obsolete
