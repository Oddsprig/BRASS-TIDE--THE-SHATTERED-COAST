PAID WORK POLICY
effortDays is the existing recovery_days equation, conservatively also bounded
by able spare crew on actual working traveling hulls. workDays=ceil(effortDays),
at least one full day, so a small extraction cannot be an unpaid fractional
click. This rounding applies only to selected gear; old strip/tow remain intact.
payrollDays=old pending_days + int(workDays), settled once; original day fraction
is preserved. Normal Economy.daily_upkeep and FleetSupport.premium determine
wages/food; coinsRequired also includes existing ordinary and specialist arrears.
No extra harbor crew or payment purse. Normal surveyFoodCredit is spent once.
Insufficient actual coins/food refuses before time, extraction or payment.

One successful action creates ONE detached Campaign context using the optional
Campaign._init(world_data,shared_navigation={}) second argument. It shares the
already warmed data/nav without rebuilding or repricing world/navigation and
owns its state/events/local route cache. Each due day uses the SAME port RNG
seed/options as Main.economy_workers, then existing Campaign.apply_economy.
No worker starts; all fallible work, carrying/custody and total-coin checks finish
before one live state/pending/events publication. Queries construct no Campaign,
world or navigation; their tiny Salvage.QuoteView clones plain state only.

PERSISTENT WEIGHT API (Expedition, pure reads)
Expedition.locker_item_weight(item: Dictionary) -> float
Expedition.locker_weight(boat: Dictionary) -> float
Expedition.hull_hold_capacity(state: Dictionary,boat: Dictionary) -> float
Expedition.cargo_weight(state) includes physical lockers on all afloat unstored
fleet hulls. HoldManifest.allocate reserves each working hull's own locker mass
before allocating shared cargo; other hull space cannot carry that locker.
Mass is max(1, sum Refits.catalog()[family][typeId].materials * Goods weights).
Stock primary/engine/armor map to existing stock rows (4,5,7 hold units).
Unknown legacy types use the conservative family maximum; an unknown family
uses the maximum across the catalog (minimum1). Canonical action catalog
validation still rejects unknown types; a weight fallback does not legalize one.
An existing physical moduleCondition is authoritative; its refitLocker count
projection is never counted again. Legacy dictionary/array count lockers still
weigh until existing migration makes them physical. Catalog data is cached once.
No Goods lot is minted for an exact physical part. Stored/sunk/unsupported
carriers cannot receive; existing unsupported lockers donate no usable hold.
Crewed traveling supportOnly boats remain eligible working physical carriers;
supportOnly is an ordinary battle-deployment choice, not a disabled-hold flag.
Existing normal trade capacity subtracts Expedition.cargo_weight, so subsequent
Goods purchases see locker mass; Manifest reserves it on that physical hull.

IN-FLIGHT MAIN ECONOMY POLICY (concrete 1139-1162 boundary)
Main.start_economy decrements pending_days BEFORE its worker completes. The
worker later replaces ports and calls apply_economy. RecoveryFlow therefore
refuses mode gear immediately when host.economy_task>=0, before any quote/action
staging or sync_economy call. Message: let the normal day finish, then retry;
no recovery work charged. It does not stop/join/control the worker or publish
an old port snapshot over a successful gear transaction. On successful gear
with no worker in flight, private settlement covers original pending_days plus
the new whole work days ONCE and publishes pending_days=0. Flow's subsequent
ordinary start/sync is then a no-op. C can exercise an artificial busy marker
without starting a worker; the core transaction itself owns no worker handle.
