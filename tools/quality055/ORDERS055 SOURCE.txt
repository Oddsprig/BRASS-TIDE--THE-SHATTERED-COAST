EXACT OBSERVATION API
NavalAI.observe(state: Dictionary, observer_id: String = "player") -> Array
  Sample current local chart contacts, update bounded dated memory, return
  detached records as below. NPC callers use their actual owner ID.
NavalAI.sightings(state: Dictionary, observer_id: String = "player") -> Array
  Read detached remembered records, with no current target lookup.
Storage: state.navalAi.sightingsByObserver[observer_id] = Array of records.
Fields: ownerId/name/faction/kind (String), x/y (float), day (fractional campaign
  day), expiresDay, destination (last observed port ID), purpose (String),
  reason (String), loaded (bool), threat (float), current (bool), ageDays,
  expired (bool). No exact cargo, purses, crew or equipment records.
reason is exclusively observation_reason(purpose), a categorical explanation;
  it never copies owner.reason/order.reason or a private repair/payroll bill.
threat is the local fleet_performance firepower estimate frozen when sighted.
Range: NPC 900, player 1800 chart units. Hidden/story contacts excluded.
Memory: max24 records per actual observer; pursuit expiry0.25 campaign days;
  dated display history retained1 day; current ages out after1.5 seconds.
  current is a sampling flag, NEVER sufficient authorization for a hail.
  The UI must recheck actual living, active, visible local contact for actions.

BOUNDED AT-SEA ORDER PUBLICATION
NavalAI.order_slice(state) -> Array of up to2 selected owner IDs. Lifecycle
runs one slice per campaign second, rotates its cursor, drops missed intervals.
The samplers first scan cheap chart coordinates and read owner/destination/load
only inside local range. Selectors consume bounded local/remembered snapshots;
no distant live destination, purse or manifest lookup remains in target choice.
Loaded means actual positive min(tradeCargo, held tradeGood), not a label.
Current diplomacy, own armed performance and observed threat bound raid and
intercept risk. Pirates seek loaded hostile carriers; patrols intercept hostile
raiders or escort nonhostile loaded carriers. Merchants retain delivery unless
nearby superior hostile strength warrants withdrawal. Actual damage/able crew,
working fuel/ammo and food/payroll reserves can require paid home recovery.
Existing recovery orders, story and player-company intent remain authoritative.
Existing authored regional corridor planner retains its separate local adapter.
Orders with a target add targetSighting (detached snapshot) and interceptPoint
{x,y}. Destination is the last observed port. Brief loss follows only the last
known point; expiry/local disappearance/nonhostility/unsafe strength drops it.
No target means retain the useful current sea leg rather than cycle fallback
ports every decision. Same intent refreshes its observation without log churn.
Paths use existing Routes.path -> Campaign.cached_path and immutable navigation
nodes/edges. A moving target requires160 chart units and >=3 seconds before a
sea-point replan. Restore's port-course rebuild is detected at publication.
One-shot response slices and old encounter caps stay distinct from daily purse,
production, payroll and funded replacement advancement. No new thread/backend.
