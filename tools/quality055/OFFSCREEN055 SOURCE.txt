DEMONSTRATED GAPS / PEER COORDINATION
1. Loot only reads loser.tradeGood/tradeCargo. A raider receives actual captured
   timber but no trader manifest; a later patrol cannot recover those held lots.
   Fix: one deterministic eligible non-operating good from a non-trader's actual
   hold can be seized, still bounded by the winner's surviving capacity. Existing
   food/fuel/ammo/supplies protection at raider/patrol docks stays intact.
2. Salvos debit and report all planned shots before discovering the last target
   sank. Move debit/count into the actual shot loop; ammoUsed includes ammoCost.
3. Replacement audit for lifecycle peer: attach_new_boat currently removes the
   first sunk hull even when wreckRecorded is false; AI.tick collects/purchases
   replacements before NavalLifecycle.daily records losses. A wiped company
   can thus lose the original wreck/equipment custody and carry its old hold
   to a new home launch. Lifecycle owner should reconcile pending wrecks/cargo
   at the actual loss coordinate BEFORE AI.tick/ready collection and before a
   zero-survivor patrol is relaunched; do not copy this code into a new backend.
   Attachment remains unchanged here: retaining dead hulls in the active roster
   would distort its existing fuel divisor/roster bookkeeping and would still
   place a late wreck at the relaunched patrol's home. This is a lifecycle-order
   dependency, not a complete fix inside replacement attachment. Root must have
   the lifecycle peer settle losses before replacement, and prove item e below,
   before accepting the integrated scope. No duplication of that backend here.
4. Ready purchase/collection chose optimal crew from recruits/workforce but
   ignored training. Economy.recruit then correctly refused if only minimum
   qualified sailors existed. available_recruits(port)->int now caps the existing
   pool by trained sailors, so both paths choose the legal paid minimum. The
   actual Economy.recruit checks, advance and finite workforce debit remain.
5. NPC merchant docking tried the entire manifest even when the market could
   afford only part. Economy.transact refused it all. Cap only NPC sale quantity
   by actual cash/sell price, leaving the remainder aboard; company rules stay.
