Diagnosis and one bounded change
- Records._battle_records051 already uses the admitted immutable descriptor
  and current engine HP/watermark guards, but allocates a five-field success
  Dictionary on every invocation. Owned absorption, transaction pre/post
  validation, snapshot refresh and projection refresh can request the same
  result repeatedly. Its consumers only read the success fields.
- Retain one read-only result on the existing owned entry, keyed by its exact
  generation and currently validated engine HP. A repeated successful read
  returns that result instead of rebuilding the five-field Dictionary.
- This changes allocation only. Every original authority/condition/items guard,
  engine unit check and watermark tolerance check still runs BEFORE reuse.
  Zero HP always constructs a fresh result to preserve signed-zero behavior.
  No public validator, public snapshot, status input or status schema changes.
